# Патчноуты

## 2.7.3 — 2026-10-16

Предыдущая версия: 2.7.2.

### Что исправлено

**Рассылка по SMTP: картинки**
- Картинки в письме не показывались в Outlook (красный крестик «Чтобы загрузить…»): в SMTP-канале они были вшиты в текст как `data:`. Теперь превращаются во встроенные вложения (`cid:`), одинаковые картинки прикладываются один раз. Письмо с картинками строится как `multipart/related`.

**Рассылка по SMTP: тишина в интерфейсе**
- Подключение к IMAP не имело таймаута: при закрытом порте рассылка висела до первого письма без единого сообщения. Теперь таймаут 15 секунд, а при недоступном IMAP в панели появляется предупреждение «Копия в «Отправленные» не сохраняется».
- Фоновый поток рассылки не перехватывал исключения: ошибка при подготовке (например, пустое значение задержки) оставляла экран на 0% навсегда. Теперь причина показывается в панели.
- Отказ сервера по адресу получателя раньше не замечался, если письмо принято для остальных адресатов. Теперь это ошибка строки с кодом и текстом ответа.

**Рассылка по SMTP: обрыв сессии**
- Если сервер закрывал SMTP-сессию после первого письма (лимит, простой, антиспам, `421`), уходило только оно: приложение не переподключалось, и остальные строки падали с «please run connect() first», не доходя до сети (в логах сервера пусто). Теперь перед каждой строкой проверяется сессия (`NOOP`), при обрыве или временном отказе `4xx` приложение переподключается и повторяет строку один раз. Отказ по адресу (`550`) по-прежнему помечает только свою строку.
- Локальная проверка: `python scripts/smtp_lab.py` поднимает поддельный SMTP-сервер и прогоняет настоящий цикл рассылки; сценарии вынесены в `tests/test_smtp_reconnect.py`.

### Что нового
- **Журнал отправки SMTP.** По каждому письму показываются время, ответ сервера и `Message-ID`; в панели виден текущий шаг рассылки. Статус «Принято сервером» не равен «доставлено» — об этом сказано в панели после рассылки. В экспорт CSV добавлены колонки «Время», «Message-ID», «Ответ сервера».
- **Текстовая версия письма** (`text/plain`) и заголовки `Date`, `Message-ID` в домене отправителя.
- Тестовое письмо по SMTP показывает ответ сервера и `Message-ID`.

### Не проверено
- Доставка письма получателям на реальном сервере: приложение теперь показывает ответ сервера, но дальнейший путь письма (CommuniGate → IronPort → Exchange) виден только в журналах почтовых серверов.
- STARTTLS на порту 25 и пауза между письмами по умолчанию не реализованы. Повтор при временных отказах (4xx) сделан только как однократное переподключение с повтором строки.

## 2.7.2 — 2026-10-14

Предыдущая версия: 2.7.1.

### Что исправлено

**Рассылка: плейсхолдеры в user-версии**
- Плейсхолдер, вставленный после загрузки Excel, «застывал» значением строки и больше не менялся; при переключении темы или потере фокуса пропадали плейсхолдеры. Причина: в режиме превью в текст холста подставлены значения строки, а при потере фокуса блок сохранял `innerHTML` как есть. Теперь, пока текст на холсте правится, значения не подставляются (видны `{{…}}`), сохранение блока всегда видит исходный текст, а превью строки возвращается, когда фокус ушёл с текста и тулбара.

**Рассылка: ссылки**
- Ссылка в значении колонки теперь оформляется как `<a>` в брендовом цвете, даже если рядом есть текст («Смотри https://…»); знаки препинания в конце адреса остаются вне ссылки.
- Плейсхолдер внутри существующей ссылки (`<a href="{{Ссылка}}">{{Ссылка}}</a>`) больше не порождает вложенный `<a>` — такие письма Evolution и Outlook показывали с нерабочей ссылкой. Плейсхолдер внутри части адреса (`href="https://…?id={{ID}}"`) подставляется как обычное значение.
- Значение в атрибуте экранируется, в том числе кавычки: значение колонки не может выйти из `href`.
- Подставленное значение не сканируется повторно, поэтому значение вида `{{Другая}}` остаётся текстом.

**Приложение**
- Клик по внешней ссылке (`http`, `https`, `mailto`, `tel`) внутри окна приложения открывает системный браузер и не уводит окно с собранным шаблоном; `target="_blank"` и `window.open` не создают новых окон.

### Что нового
- **Разделитель: ширина.** В настройках блока флажок «На всю ширину письма» (по умолчанию включён, как раньше). Если выключить, разделитель выравнивается по боковым отступам основного контента (`settings.fullWidth`).

### Не проверено
- «Размытость» рассылок: на стороне приложения картинки блоков рендерятся с запасом по разрешению (баннер — 1200px под 600px, остальные — ×2), серверная часть картинки не пережимает. Нужен конкретный образец письма и клиент, где видно размытие.

## 2.7.1 — 2026-10-09

Предыдущая версия: 2.6.2.

### Что исправлено

**Рассылка: вложения**
- Режим вложений «Колонка» был в интерфейсе, но не работал: панель не отправляла выбранную колонку, а сервер искал файл только по шаблону имени. Теперь имя файла берётся из выбранной колонки таблицы.
- В шаблоне имени файла можно использовать колонку, которой нет в теле письма: `{{Файл}}.docx` берёт значение из колонки «Файл».
- Поиск файла стал терпимым к различиям между ячейкой Excel и именем на диске: регистр, «ё»/«е», вид юникода, лишние пробелы.
- Имя без расширения («Условия активации») находит файл, только если он единственный. Если рядом лежат `Договор.docx` и `Договор.pdf`, вложение не прикладывается, а в `protocol.log` попадает предупреждение со списком кандидатов — чтобы письмо не ушло с чужим файлом.
- Перед отправкой панель проверяет настройки вложений: без папки, колонки или шаблона имени покажет предупреждение вместо молчаливой отправки без вложения.
- Список файлов папки читается один раз на рассылку, а не на каждую строку.
- В `protocol.log` при старте рассылки пишется строка с настройками вложений для диагностики.

**Рассылка: отложенная отправка**
- Письма с отложенной отправкой лежали в «Исходящих» как неотправленные черновики и не уходили: приложение только сохраняло их (`save()`), а серверная очередь Exchange такие письма не берёт. Теперь письмо отправляется (`send()`) с правильным свойством времени доставки `PidTagDeferredSendTime` (0x3FEF) — сервер удерживает его до указанного времени. Раньше пробовали либо `send()` с неверным тегом 0x000F, либо верный тег с `save()`. Сочетание «верный тег + `send()`» проверено тестовым письмом на реальном Exchange (2026-10-12): письмо ушло в назначенное время.
- Черновики, уже оставшиеся в «Исходящих» от прежних попыток, нужно удалить вручную.
- Некорректная дата отложенной отправки раньше игнорировалась, и вся рассылка уходила сразу. Теперь рассылка прерывается с понятным сообщением.
- Канал SMTP не умеет отложенную доставку: раньше письма уходили сразу, а в прогрессе писалось «Запланировано». Теперь рассылка по SMTP с включённым чекбоксом не стартует.
- Режим «Черновик» вместе с отложенной отправкой тоже не стартует (расписание в черновиках не работает).
- Проверка «дата в будущем» на сервере учитывает часовой пояс пользователя, а не часовой пояс компьютера сервера.
- Те же проверки выполняются в панели до окна подтверждения.
- Тесты `test_send_at_*` использовали жёсткую дату 2026-09-01 и после неё стали падать; переписаны на относительную дату.

**Рассылка: плейсхолдеры**
- Плейсхолдеры из темы письма и шаблона имени файла попадают в общий список сопоставления колонок. Вставлять их в тело письма не нужно.
- При вводе нового плейсхолдера в тему или шаблон имени уже выбранные сопоставления тела письма больше не сбрасываются (причина — поиск плейсхолдеров читал канвас, где в режиме превью уже подставлены значения строки). Осознанное «не задано» тоже сохраняется.
- После вставки поля через панель форматирования превью выбранной строки возвращается.

**Баннер**
- Градиент баннера в user-версии больше не пропадает при смене текста: user-страница не получала математику градиента, потому что сервер блокирует `js/settings/*` в user-режиме. Код вынесен в `static/js/shared/bannerGradient.js`.
- Пользователь по-прежнему не редактирует градиент, но может заменить его сплошным цветом: выбор цвета отключает градиент выбранной области.

**Письмо: старые шаблоны и боковые отступы**
- Изображения, «Эксперт» и «Свободный блок» ограничиваются доступной шириной блока (колонка или слот письма за вычетом бокового отступа профиля и отступа подложки). Старые шаблоны с картинками под 600px больше не вылезают за слот и не «прилипают» к левому краю.
- Контекст ширины при генерации блока восстанавливается через `try/finally`.

**Кнопки в колонках**
- Слипание кнопок в ряду из 4 колонок: причиной был `table-layout:fixed` (с августа) вместе с шириной колонок от слота письма за вычетом отступов; картинка кнопки шире ячейки заезжала на соседнюю. Теперь колонки с широкими кнопками расширяются за счёт остальных, сумма ширин ряда сохраняется.
- Пока ширину колонок не меняли вручную, подгонка включена; любое ручное изменение (пресеты, ползунок, числовые поля) её отключает. Флажок «Подгонять ширину колонок под кнопки» в настройках ряда возвращает автоматику (настройка `colWidthManual`).
- Если кнопкам вместе не хватает места, ширины остаются заданными пользователем.

**Категории шаблонов**
- Диалог сохранения шаблона: все отступы и размеры блока категории кратны 4px, кнопка «+ Новая», строка «Создать / Отмена», Escape закрывает ввод.
- Категория добавляется в список только после ответа сервера; при ошибке показывается уведомление. Повторное имя не дублируется.

### Что нового
- **Цвет выделенного текста.** Кнопка в панели форматирования текстового блока красит только выделенный фрагмент, включая `{{плейсхолдер}}`. Выделение на нескольких абзацах красится по абзацам, выделение внутри уже окрашенного текста разрезает его, «Без цвета» снимает окраску. В блоке «Заголовок» кнопка скрыта (он хранит чистый текст). Санитайзер сохраняет только такие спаны и только с цветом `#rrggbb`; цвета из вставленного Word/HTML отбрасываются.
