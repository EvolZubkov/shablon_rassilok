# Почтелье

Десктопное приложение для создания и отправки HTML-писем и встреч через Microsoft Exchange (EWS).

Текущая версия: **2.8.0** (история изменений — [docs/PATCHNOTES.md](docs/PATCHNOTES.md)).

Запускается как локальный Flask-сервер со встроенным Chromium-окном (PyQt5 + QWebEngineView). Работает на Windows и ALT Linux.

## UI Rules

Для всего проекта действует жёсткое правило `4px` grid.

- Все визуальные размеры и отступы должны быть кратны `4px`.
- Интервал между соседними элементами интерфейса: `4px`, если в задаче явно не задано другое значение.
- Хаотичный перенос кнопок и layout "как получится" запрещены.

Полные правила зафиксированы в [AGENTS.md](/mnt/c/Repositories/shablon_rassilok/AGENTS.md).

## Архитектура

```text
Pochtelye.exe / Pochtelye (Linux)
    |
    +-- Flask (localhost:7788)          веб-интерфейс + API
    +-- QWebEngineView                  окно приложения (Chromium)
```

## Режимы работы

| Режим         | Условие запуска                    | Возможности                                       |
| ------------- | ---------------------------------- | ------------------------------------------------- |
| Пользователь  | По умолчанию                       | Просмотр и отправка писем                         |

### config.ini

```ini
[app]
; Путь к сетевой папке с ресурсами
network_path_win         = \\server\share\email-builder        ; Windows
network_path_smb         = //server/share/email-builder        ; Linux (SMB URL)
network_path_linux_hint  = email-builder                       ; имя папки для поиска

; Порт локального сервера
port = 7788
```

## Сетевая папка (ресурсы)

Приложение читает ресурсы из сетевой папки и кеширует их локально. Структура папки на сервере:

```text
email-builder/
    version.txt               версия ресурсов (строка, например 20240101.1)
    static/
        config.json           конфигурация контента
        icons/
        expert-badges/
        bullets/
        button-icons/
        images/
        dividers/
        banner-backgrounds/
        banner-logos/
        banner-icons/
        fonts/
```

При первом запуске кеш заполняется автоматически. При последующих запусках сравниваются версии: если `version.txt` на сервере изменился -- предлагается обновление.

Если сетевая папка недоступна -- приложение работает из локального кеша.

## Рассылка по таблице

Пользователь загружает Excel или ODS, часть колонок использует в письме, часть — в теме и в имени вложения. Плейсхолдер `{{Колонка}}` можно писать в любом из трёх мест, вставлять его в тело письма не обязательно.

- **Плейсхолдеры.** Панель ищет `{{…}}` в теле письма, в теме и (при включённых вложениях по шаблону) в шаблоне имени файла и собирает общий список «плейсхолдер → колонка». Новые плейсхолдеры сопоставляются по названию колонки автоматически. Выбранные пользователем сопоставления, в том числе «не задано», при правке темы или шаблона не сбрасываются.
- **Вложения.** Два режима:
  - *Шаблон имени* — например `{{ФИО}}.docx` или `{{Файл}}.pdf`; `{{Название}}`, которого нет в сопоставлении, берётся из колонки с таким же названием.
  - *Колонка* — имя файла целиком берётся из выбранной колонки таблицы.
- **Поиск файла.** Сначала точное имя, затем без учёта регистра, «ё»/«е», вида юникода (NFC/NFD) и лишних пробелов. Имя без расширения («Условия активации») находит файл, только если такой файл один: при нескольких (`.docx` и `.pdf`) вложение не прикладывается и в `protocol.log` пишется предупреждение со списком кандидатов — приложение не угадывает, какой файл отправить. Список файлов папки читается один раз на рассылку.
- **Проверка перед отправкой.** Если вложения включены, а папка, колонка или шаблон имени не заданы, панель покажет предупреждение вместо молчаливой отправки без вложения.
- **Отложенная отправка.** Чекбокс «Отложенная отправка» доступен только для канала Exchange: письмо отправляется через EWS с серверным свойством отложенной доставки `PidTagDeferredSendTime` (0x3FEF), Exchange держит его в очереди до указанного времени, приложение открытым оставлять не нужно. Копия сразу видна в «Отправленных», в «Исходящих» письма не остаются. Время задаётся в часовом поясе пользователя. Рассылка не стартует, если дата не указана или в прошлом, выбран канал SMTP или включён режим «Черновик»; письма при этом не уходят сразу. Те же проверки панель выполняет до окна подтверждения.
- **Канал SMTP: что видно по каждому письму.** Список результатов показывает время, ответ сервера (`250 … queued as …`) и `Message-ID`; полная подсказка — при наведении на строку. Статус «Принято сервером» означает, что сервер взял письмо, а не что оно дошло: судьбу письма дальше видно только в журнале почтового сервера, администратору передаётся `Message-ID`. Отказ сервера по адресу получателя показывается ошибкой строки с кодом (например, `550`), а не успехом. Над списком выводятся шаги («Подключаюсь…», «Отправляю 3 из 50: …») и предупреждения, например что копия в «Отправленные» не сохраняется. Экспорт CSV содержит колонки «Время», «Message-ID» и «Ответ сервера».
- **Канал SMTP: вид письма.** Картинки блоков уходят встроенными вложениями (`cid:`), как в Exchange-канале, и отображаются в Outlook; раньше они были вшиты в текст (`data:`) и показывались красным крестиком. К письму добавляется текстовая версия, `Date` и `Message-ID` задаются приложением. Подключение к IMAP ограничено 15 секундами.
- **Диагностика.** В начале рассылки в `protocol.log` пишется строка `bulk_send: attachments on — folder=… mode=… column=… template=…`.

## Форматирование текста и баннеры

- **Цвет фрагмента.** В панели форматирования текстового блока есть кнопка «Цвет выделенного текста»: красится только выделение (в том числе `{{плейсхолдер}}`), «Без цвета» снимает окраску. Выделение на нескольких абзацах красится по абзацам. В блоке «Заголовок» (он хранит чистый текст) кнопка скрыта. Санитайзер сохраняет только цвет, заданный этой кнопкой (`<span data-tc="#rrggbb">`), цвета из вставленного Word/HTML отбрасываются.
- **Градиент баннера.** Пользователь не редактирует градиент, но может заменить его сплошным цветом: выбор цвета отключает градиент выбранной области.

## Особенности user-режима

В user-режиме сервер отдаёт 404 на всё из `static/js/settings/` (см. `routes/static_files.py`, `admin_js_prefixes`). Код, который нужен и пользователю, и админу, должен лежать вне этой папки — например, математика градиента баннера вынесена в `static/js/shared/bannerGradient.js`. Правки статических скриптов, которые окно могло закэшировать, сопровождаются параметром версии в теге `<script>` (например, `bulk-mail-panel.js?v=…`).

## Письмо: ширина блоков и боковые отступы

Контентная колонка письма уже полной ширины на величину бокового `contentPadding` профиля. Изображения, блоки «Эксперт» и «Свободный блок» ограничиваются доступной шириной (колонка либо слот письма за вычетом отступов подложки), поэтому старые шаблоны с картинками под 600px не вылезают за слот и не «прилипают» к левому краю. Исключение — баннер и разделитель: они остаются на всю ширину.

- **Кнопки в колонках.** Таблица колонок в письме имеет фиксированную раскладку (`table-layout:fixed`), поэтому кнопка шире своей ячейки раньше заезжала на соседнюю. Теперь, пока ширина колонок не менялась вручную, колонки с широкими кнопками расширяются за счёт остальных (общая ширина ряда сохраняется, картинка кнопки не сжимается). Ручное изменение ширины в настройках колонок (пресеты, ползунок, поля) отключает подгонку, вернуть её можно флажком «Подгонять ширину колонок под кнопки». Если кнопкам вместе не хватает места, ширины остаются как заданы.

## Сборка

### Windows

```bat
pyinstaller build.spec --noconfirm
```

Результат: `dist\Pochtelye.exe`

### ALT Linux (через Docker с Windows-хоста)

```bat
build_linux_alt.bat
```

Результат: `dist\linux\Pochtelye`

### Подготовка перед сборкой

Перед сборкой с поддержкой режима администратора необходимо сгенерировать хеш токена:

```shell
python scripts/sync_version.py --gen-token "ваш_секретный_токен"
```

Команда создаёт `.key` (секрет) и `.admin_hash` (хеш), который зашивается в исполняемый файл при сборке.

## Управление версией

Единственный источник версии -- `pyproject.toml`:

```toml
[project]
version = "1.2.3"
```

После изменения версии выполнить:

```shell
python scripts/sync_version.py
```

Команда синхронизирует `_version.py` и `package.json`.

## Администрирование токена

### Файлы

| Файл | Где хранится | Назначение |
| --- | --- | --- |
| `.key` | Корень проекта, не в git | Исходный секрет. Хранить в надёжном месте |
| `.admin_hash` | Корень проекта, не в git | SHA-256 хеш. Зашивается в `.exe` при сборке |
| `.lic` | Рядом с `.exe` на машине администратора | Секрет для проверки при запуске |

### Первоначальная настройка

```shell
python scripts/sync_version.py --gen-token "случайная_строка"
```

Создаёт `.key` (секрет) и `.admin_hash` (хеш). Собрать `.exe` -- хеш зашит внутрь.

### Выдача доступа администратору

```shell
python scripts/sync_version.py --make-lic
```

Читает `.key`, создаёт `.lic`. Скопировать `.lic` рядом с `.exe` на машину администратора.
